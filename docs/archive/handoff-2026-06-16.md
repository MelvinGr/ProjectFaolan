## 1. #23 — mid-session entity spawn (CRACKED, committed `0827af5`)

**Root cause: the playfield token.** Mid-session spawns (`.spawnnpc`, mount, interest-streaming, NPC respawn,
loot bags) carried the playfield-instance token from whatever capture session the row/template was built in
(e.g. a beach Crocodile row's `0x01EA985C`), NOT this session's live token (`0x004FE428`). The client looks a
spawn's playfield up in its loaded-playfield map and silently drops a miss **before it ever polls `0x2020`** for
the handle → never renders. The login burst rendered only because it was replayed from the same session whose
token IS the live one.

**Fix:** `WorldBroadcaster.SendWorldSpawn` + `MakeCorpseLootable` re-stamp the body's token to the live
`Zone.PlayfieldToken` via the existing `SpawnPlayfieldRewriter`. **Verified in-client**: a `.spawnnpc` drew the
first mid-session `0x2020` poll + `0x2008` SpawnCheck in the project's history and rendered.

**The long-documented "stateful conversation / `PollStatus` keepalive" theory (docs parts 4-7) was DISPROVEN
in-client** this session: a continuous `BehaviorControlCenterIIR` heartbeat kept the world conversation provably
alive (1834 packets) and the client *still* didn't poll a mid-session spawn. Part 3 (playfield token) was right.
Memory `protocol_midsession_spawn_blocked` + `docs/subsystems/mid-session-spawn-blocker.md` updated to SOLVED.

**Open (Gitea #226):** (a) the window lists one fewer than granted when a rolled item isn't client-displayable
